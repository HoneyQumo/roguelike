# Спрайт-комплект · что где лежит и как подключить

## Файлы

| Файл | Что это |
|---|---|
| `player.png` | ГГ, 768×1152. Строки 0–7 — общие анимации, 8 — мощная атака, 9 — смена оружия, 10–17 — направления кувырка |
| `enemy_grunt/assault/shield/heavy/radio/boss.png` | шесть типов врагов, 768×512. Строки те же 0–7, кувырка нет |
| `weapons.png` | 11 стволов СВЕРХУ, в руках. 640×704. Строка = ствол, столбец = вариант хвата |
| `weapons_side.png` | те же 11 стволов СБОКУ, 224×352. Лут на полу, инвентарь, HUD |
| `fx/fx.png` | все эффекты одной текстурой, прямоугольники в `character.json` |
| `fx/hit_flash.frag` | шейдер белой вспышки урона |
| `character.json` | раскладка, тайминги, пивоты, покадровые таблицы |
| `weapons.json` | дульный срез, отдача, размер вспышки по стволам |
| `sfml_example.cpp` | рабочий референс, компилируется и запускается |
| `SPRITE_SPEC.md` | почему всё сделано именно так |

## Три правила, без которых развалится

1. **`texture.setSmooth(false)`** на всех текстурах. Иначе поворот превратит
   пиксель-арт в кашу.
2. **Тело и оружие рисуются в одной позиции с одним углом.** Отличаются только
   `origin`: тело `(32,32)`, оружие `(80,32)`. Никакой тригонометрии для
   крепления ствола к рукам не нужно.
3. **Сцену рендерить в `sf::RenderTexture` нативного размера** и растягивать
   целым множителем. Дробный масштаб делает пиксель неквадратным.

## Как рисовать персонажа

```cpp
float angle = std::atan2(aim.y - pos.y, aim.x - pos.x) * 180.f / 3.14159265f;

body.setTextureRect({frame * 64, row * 64, 64, 64});
body.setOrigin(32.f, 32.f);
body.setPosition(pos);  body.setRotation(angle);  rt.draw(body);

weapon.setTextureRect({variant * 160, weaponRow * 64, 160, 64});
weapon.setOrigin(80.f, 32.f);
weapon.setPosition(pos + rotate(weaponOffset, angle));   // offset из JSON
weapon.setRotation(angle);  rt.draw(weapon);
```

`weapon_offset` в JSON задан **в пикселях кадра**: повернуть на угол прицела
и прибавить к позиции. Так же ставятся вспышка, брызги и предмет в руке.

## Строки атласа тела

| Строка | Анимация | Кадров | мс | Луп |
|---|---|---|---|---|
| 0 | idle | 6 | 175 | да |
| 1 | walk | 8 | 110 | да |
| 2 | run | 8 | 75 | да |
| 3 | shoot | 4 | 60 | нет |
| 4 | reload | 12 | 90 | нет |
| 5 | melee | 6 | 60 | нет |
| 6 | hurt | 3 | 80 | нет |
| 7 | death | 8 | 110 | нет |
| 8 | heavy — мощная атака, **только ГГ** | 12 | `frame_ms` | нет |
| 9 | swap — смена оружия, **только ГГ** | 10 | `frame_ms` | нет |
| 10–17 | roll, строка = направление | 10 | 50 | нет |

Строки 0–7 одинаковы у ГГ и у противников. Строки 8 и 9 есть только в
`player.png`, поэтому раскладка `enemy_*.png` не сдвинулась и старый код,
читающий строки 0–7, продолжает работать без правок.

## Ближний бой: две атаки

| | Строка | Кадров | Тайминг | Попадание |
|---|---|---|---|---|
| Быстрая | 5 `melee` | 6 | 60 мс | кадр 3 |
| Мощная | 8 `heavy` | 12 | `frame_ms` | кадры 8–9 |

Обе крутят **слой оружия** поверх угла прицела — `weapon_rot` из JSON.
Пивот слоя совпадает с пивотом тела, поэтому оружие идёт дугой вокруг
корпуса, а руки остаются на рукояти сами:

```cpp
weapon.setRotation(angle + WEAPON_ROT[frame]);   // тело — просто angle
```

### Мощная атака: заряжаемая

| Кадры | Фаза |
|---|---|
| 0–2 | занос |
| 3–4 | петля набора заряда — крутится, пока кнопка зажата |
| 5–6 | петля «заряд набран» — поза туже, тремор 1 px |
| 7–9 | удар с шагом, попадание на 8–9 |
| 10–11 | восстановление |

```cpp
// удержание НЕ растягивает кадр, а ПОВТОРЯЕТ петлю: растянутый кадр
// читается как подвисшая игра, повтор — как накопление
if (inLoop) {
    if (!holding) frame = release_from;              // = 7
    else          frame = nextInLoop(charged);       // 3-4, затем 5-6
}
pos += aimDir * heavySpeed * move_speed[frame] * dt;
```

`frame_ms` обязателен: занос идёт по 85–110 мс, удар по 34 мс, и именно
этот контраст читается как вес. Поле `ms` у этой строки — среднее, его
использовать нельзя.

`move_speed` в петлях нулевой: иначе персонаж будет уезжать всё время,
пока игрок копит заряд.

Свечение «заряд набран» — пульс уже готовым `fx/hit_flash.frag` на
амплитуде 0.22, тем же шейдером, что белая вспышка урона. Отдельных
кадров под него в атласе нет и не нужно:

```cpp
float glow = std::max(hitFlash, charged ? 0.22f * pulse : 0.f);
```

## Кувырок: выбор строки

Направление считается **относительно прицела**, не относительно мира.
Восемь строк так покрывают все направления, и ствол остаётся на цели.

```cpp
float rel = std::atan2(move.y, move.x) - std::atan2(aim.y, aim.x);
int   row = 10 + ((int)std::lround(rel * 4.f / 3.14159265f) % 8 + 8) % 8;
pos += moveDir * dashSpeed * moveSpeed[frame] * dt;   // move_speed из JSON
```

`move_speed` обязателен: без него персонаж поедет на вставании и зависнет
в полёте. `invuln_frames` = `[2..7]` — кадры неуязвимости, крутите под баланс.

## Оружие: столбцы

| Столбец | Когда |
|---|---|
| 0 | обычный хват |
| 1 | без поддерживающей перчатки |
| 2 | без перчатки и без магазина |
| 3 | **без перчаток вовсе** — ствол сам по себе: убранный за спину, на стойке, в витрине |

Перезарядка переключает столбец по кадрам — таблица `weapon_variant`
в `character.json`. Строки стволов: 0 ak47, 1 m16, 2 shotgun_double,
3 shotgun_pump, 4 smg_suppressed, 5 glock, 6 deagle, 7 pistol_suppressed,
8 knife, 9 bat, 10 rpg. В `weapons_side.png` тот же порядок строк.

## Смена оружия

Строка 9, 10 кадров, 545 мс, `frame_ms` обязателен.

| Кадры | Фаза |
|---|---|
| 0–1 | старый ствол опускается, кисть сходит с цевья (столбец 1) |
| 2–5 | **руки пустые**, 265 мс. Старый ствол едет за спину |
| 6–7 | новый ствол выходит в хват |
| 8–9 | осадка в стойку |

**`swap_frame` = 5** — кадр, на котором движок меняет СТРОКУ оружия.
Он внутри `weapon_hidden`: подмена спрайта на видимом кадре читается
как рывок.

```cpp
// строка меняется ровно на swap_frame, поэтому новый ствол ждёт своей очереди
if (state == SWAP && frame + 1 == SWAP_FRAME && pending >= 0) {
    weapon = pending; pending = -1;
}
```

Убранный ствол — **отдельный слой ПОД телом**, он не запечён в кадры:

```cpp
sf::Sprite s(wpn, {3 * 160, oldWeaponRow * 64, 160, 64});   // столбец 3
s.setOrigin(80.f, 32.f);
s.setPosition(pos + rotate(stow_anchor[frame], angle));
s.setRotation(angle + stow_rot[frame]);      // угол СВОЙ на каждом кадре
```

Столбец 3 (без перчаток) добавлен ради этого: в столбцах 0–2 перчатки
запечены, и на бесхозном стволе они читаются как тёмные комки.
`stow_rot` меняется по кадрам — при одном фиксированном угле ствол только
едет вместе с персонажем и выглядит приклеенным.

Окно с пустыми руками — это и есть цена смены: перезарядку такой сменой
не отменить. Если нужен разрыв анимации (например, кувырком) — рвать
можно, но тогда решите, откатывается ли ствол к старому или смена
считается завершённой.

## Оружие сбоку: лут, инвентарь, HUD

Кадр 112×32, пивот в центре `(56,16)`, строка = тот же ствол, столбец
0 обычный, 1 подсвеченный.

Масштаб тот же, что у вида сверху: АК на полу ровно такой же длины, как
АК в руках, и при подборе ствол не «вырастает». Один спрайт закрывает все
три применения — на полу, в инвентаре, в HUD.

```cpp
// на полу: поворот НЕ применять, предмет лежит
sf::Sprite s(side, {lit ? 112 : 0, row * 32, 112, 32});
s.setOrigin(56.f, 16.f);
s.setPosition(lootPos);
s.setScale(flip ? -1.f : 1.f, 1.f);   // зеркало по X для разнообразия

// в HUD: тот же кадр, обрезанный по side_bbox из weapons.json
sf::Sprite i(side, {b.x, row * 32 + b.y, b.w, b.h});
```

Столбец 1 — состояние «можно поднять»: светлый ободок вместо тёмной
обводки. Ободок, а не перекраска: у стволов разные материалы, и
осветление корпуса на дереве и на вороненой стали читается по-разному.

Рисовать лут ДО тел, чтобы персонаж проходил поверх лежащего ствола.
Поворачивать лежащий предмет не надо — дробный угол рвёт пиксельную
сетку; для разнообразия хватает отражения по X.

`side_bbox` — занятый прямоугольник внутри кадра. По нему интерфейс
обрезает рамку под инвентарную ячейку, не зашивая размеры стволов в код.

## Эффекты в fx.png

Прямоугольник каждой группы лежит в `character.json` → `atlas.fx.rects`.
Кадр `i` группы: `{x + w*i, y, w, h}`.

| Группа | Кадров | Как ставить |
|---|---|---|
| `muzzle_flash` | 3 | в `muzzle_offset` из weapons.json, поворот на угол прицела, размер × `flash_scale` |
| `bullet` | 3 | 0 винтовочный, 1 пистолетный, 2 дробь. Поворот на угол полёта |
| `impact` | 4 | искры в стену, поворот на угол нормали поверхности |
| `explosion` | 7 | взрыв РПГ, поворот не нужен |
| `blood_pool` | 10 | **под телом**, тот же пивот и угол, что у трупа |
| `blood_hit` | 4 | брызги, поворот на угол урона, спавнить 1–2 с разбросом ±20° |
| `blood_speck` | 1 | декаль на полу |
| `shell_fly` | 4 | гильза крутится |
| `rocket` | 2 | ракета в полёте |
| `hand_item` | 6 | магазины/гильза/ракета в руке: `mag_rifle, mag_smg, mag_pistol, shell, rocket, stowed` |
| `pickup` | 6 | пары «обычный / подсвеченный»: аптечка, патроны, броня. **Поворот не применять** |

## Порядок отрисовки

```
blood_pool → body → weapon → hand_item → muzzle_flash → blood_hit
```

## Вспышка урона

```cpp
hit.setUniform("texture", sf::Shader::CurrentTexture);
hit.setUniform("amount", flash);        // 1.0 в момент попадания
rt.draw(body, &hit);  rt.draw(weapon, &hit);
flash = std::max(0.f, flash - dt / 0.12f);
```

Шейдером, а не кадрами: вспышка нужна поверх любого кадра любой анимации.

## Смерть

Четыре флага из JSON: после `drop_frame` (=1) заспавнить ствол лутом на
полу — кадр из `weapons_side.png`, не из `weapons.png`. С кадра 3 запустить лужу
(свой таймер 150 мс, продолжает расти после конца анимации). В конце
`hold_last_frame` — перестать обновлять кадр, и `freeze_rotation` — заморозить
угол, иначе труп будет доворачиваться за прицелом.

## Враги

Два разных рычага:

* **Перекраска** — шесть значений цвета корпуса и рукавов, `recolor_slots`
  в JSON. Ноль новых кадров, тот же атлас.
* **Силуэтная надстройка** — ранец, баллоны, антенна, щит, ширина плеч.
  Меняет контур, поэтому у каждого типа своя текстура.

Кувырок только у ГГ.

## Собрать демо

```
g++ -std=c++17 sfml_example.cpp -o demo -lsfml-graphics -lsfml-window -lsfml-system
```

Запускать из папки, где лежит `assets/`. WASD движение, мышь прицел,
ЛКМ огонь, ПКМ держать — мощный заряжаемый удар (отпустить = ударить),
Space кувырок, R перезарядка, F быстрый удар, 1–9 смена ствола
(с анимацией), K смерть, E поднять ствол с пола, G выбросить свой.

Константы раскладки в примере продублированы намеренно — он не тащит
json-библиотеку. В боевом коде читайте `character.json`.
