# Правила проекта

## Задачи

У каждой задачи есть код вида `F-<область>-<номер>`, он идёт первым в заголовке через `·`:

```
F-GPL-41 · Локация: мост над пропастью
```

| область | о чём | метка |
|---|---|---|
| `F-GPL` | игровая логика, ИИ, предметы, локации | `gameplay` |
| `F-GFX` | спрайты, тайлы, эффекты, звук | `gfx` |
| `F-UI` | экраны, HUD, меню | `UI` |
| `F-ENG` | движок, физика, сборка, CI | `infra` |
| `F-DOC` | документация и сценарий | `documentation` |

Номер выдаётся следующим свободным внутри области - посмотреть занятые можно так:

```bash
gh issue list --state all --limit 200 --json title --jq '.[].title' | grep -o 'F-[A-Z]*-[0-9]*' | sort -u
```

### Метки

Обязательны две: **область** и, если это дефект, **`bug`**. Баг без метки `bug` - ошибка оформления.

Метки сложности (`difficulty:easy|medium|hard`) и спринта ставятся по желанию, задним числом их не проставляем.

### Подзадачи

Крупная задача дробится на части, и части привязываются к родителю настоящей иерархией GitHub - sub-issues, а не строчкой в описании. Тогда у родителя виден список с прогрессом, а у части - хлебная крошка вверху.

```bash
# узнать id подзадачи (это не её номер)
gh api repos/HoneyQumo/roguelike/issues/195 --jq .id

# привязать к родителю
gh api --method POST repos/HoneyQumo/roguelike/issues/152/sub_issues -F sub_issue_id=<id>

# посмотреть, что уже привязано
gh api repos/HoneyQumo/roguelike/issues/152/sub_issues --jq '.[]|"\(.number) \(.state) \(.title)"'
```

Вложенность может быть глубже одного уровня: локация моста сама висит подзадачей акта.

## Ветки

Имя ветки начинается с типа работы и содержит код задачи:

```
feat/F-GPL-41__bridge-waves
bug/F-GFX-22__car-proportions
refactor/F-ENG-8__physics-separation
```

| префикс | когда |
|---|---|
| `feat/` | новая возможность или контент |
| `bug/` | исправление дефекта |
| `refactor/` | перестройка без смены поведения |

После кода задачи идёт `__` и короткое описание латиницей через дефис.

## Процесс

Одна задача - одна ветка - один MR. Заголовок MR начинается с кода задачи, в теле - `Closes #<номер>` английским ключевым словом, иначе GitHub не закроет задачу автоматически.

Вливать только с зелёным CI, squash-мержем.

## Управление

Две клавиши взаимодействия, и смысл у них разный:

| клавиша | действие | что |
|---|---|---|
| **E** | `InputAction::Interact` | взять, открыть ящик, дёрнуть рычаг |
| **F** | `InputAction::Pass` | пройти: дверь, люк, машина, переход на локацию |

Новый интерактивный компонент переопределяет `GetAction()` осознанно, а не наследует по умолчанию. Текст подсказки обязан называть ту же клавишу - за этим следит `InteractKeysTest`.

## Стиль

Тексты коммитов, MR и комментариев - короткие, по делу, с коротким тире `-`. Без подписей и упоминаний инструментов.

Комментарии в коде объясняют **почему**, а не что: строчка над неочевидным решением, а не пересказ соседней строки.
